# Character Knowledge Builder

인물의 생활과 정보 경로를 함께 설계하라. 인물이 무엇을 했는지보다 **그때 무엇을 알았고, 어디에 있었고, 어떻게 말하는 사람인지**가 모순 없이 이어져야 한다.

| 작업 | 참조 |
|---|---|
| 정체성·소속·동선·말투 | [인물 프로필과 말투](references/profile-and-voice.md) |
| 시점별 지식·믿음·주장·거짓말 | [정보 비대칭 계약](references/knowledge.md) |

## 실행

1. 인물의 공적 정체성, 실제 정체성, 생업·습관·관계, 욕구·두려움·비밀을 구별하라.
2. 조직 소속은 affiliations에 역할과 기간으로 적어라. 직위와 권한 구조 자체는 World Builder의 조직 설정을 따른다.
3. 거주지와 일과로 평소 동선을 정하라. 사건 속 위치는 Plot Builder의 Event.location_id와 맞춘다.
4. 메시지·메일로 드러나는 인물은 말투 프로필(voice)을 정하라.
5. 사건의 각 중요한 행동을 당시 목표·정보·제약과 연결하라.
6. 무엇을 언제 어떤 경로로 알거나 믿었는지 Knowledge로 기록하라. 지식 획득 시점과 사건 발생 시점을 혼동하지 마라.
7. 인식 상태와 실제로 한 주장을 분리하라. 거짓말은 fact_ids로 숨기는 진실을 가리키고, 그 시점의 Knowledge와 연결하라.
8. 관계와 정보 비대칭이 플레이어의 조사와 선택에서 어떤 의미를 갖는지 전달하라.

Character·Knowledge·Claim 객체를 소유한다. 인물이 믿는 내용을 Fact로 승격하지 마라. 작성자가 알 수 없는 세부사항을 문서 개요에 넣지 말고, 우연히 맞힌 추측은 추측으로 표시하라. 다른 사람의 속마음을 이유 없이 확실히 안다고 쓰지 마라.

## 점검

구조화 snapshot이 있으면 `canon.py timeline snapshot.json --character 인물ID`로 그 인물의 소속·사건·기록·앎·발언을 시간순으로 보고, `canon.py validate`에서 다음 규칙을 확인하라.

| 규칙 | 인물 설계에서의 의미 |
|---|---|
| TIME-004 | 정보를 얻기 전에 알고 있다 |
| TIME-007 | 소속 기간 밖에 조직으로서 행동했다 |
| SPACE-002 / SPACE-003 | 같은 시각에 두 장소에 있거나, 이동 시간이 부족하다 |
| CLAIM-001 | 거짓말인데 숨기는 진실이 없거나, 그때 그 진실을 몰랐다 |
| TERM-001 | 인물 서술에 금지 별칭이 섞였다. 다만 인물이 일부러 틀린 이름을 쓰는 것은 말투 프로필에 적는다 |

## 공통 계약

이 묶음은 게임마다 독립 세계를 만들고, 고정된 과거 진상과 플레이어 선택에 따른 결말을 연결한 기획서를 완성한다. 사건 밖의 운영·문화·서비스·인물 일상도 설계한다.

현재 `project_id`, `version_id`, 기준 리비전과 관련 확정 설정부터 읽는다. 다른 프로젝트·버전의 설정을 자동 상속하지 않는다. 사용자 결정은 CONFIRMED, AI의 새 창작은 PROPOSED로 구별한다. 이번 요청이 이미 승인한 범위를 반복 승인받지 않는다. 선택에서 필연적으로 따라오는 제약과 추가 가정을 구별한다.

설정 수정은 담당 영역의 변경안으로 반환한다. 타 영역을 바꿔야 하면 대상 ID·이유·영향을 명시한다. 저장 성공은 실제 도구 결과를 확인한 경우에만 보고한다. 출력은 변경 내용, 결정 근거, 미정 항목, 검토 이슈, 다음 작업을 포함한다.

구조화 파일·동기화가 필요하면 같은 묶음의 `notion-canon-manager`를 이름으로 찾아 `references/data-contract.md`를 읽는다. 저장 경로는 설치 시 달라질 수 있으므로 다른 스킬의 절대 경로나 생성 ID를 하드코딩하지 않는다. 함께 설치된 스킬이 없으면 해당 의존성을 알리고 초안은 이어가되 연동 완료를 주장하지 않는다.

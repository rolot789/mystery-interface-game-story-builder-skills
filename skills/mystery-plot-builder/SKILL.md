# Mystery Plot Builder

[사건·분기 설계](references/plot-and-branches.md)를 읽고 관련 세계·인물 결정에서 시작하라. 전체 줄거리를 일방적으로 확정하지 말고 현재 핵심 쟁점의 대안과 파급을 제시하라.

## 실행

1. 조사 현재 시점(charter.present_at)과 실제 과거 사건의 경계를 정하라. 헌장은 World Builder가 소유하므로 현재 시점 변경은 제안으로 전달하라. 인물의 주장과 진상을 분리하라.
2. 각 주요 사건에 선행 조건, 행위자, 행동, 결과, 시각(TimeSpec), 장소(location_id)와 지속 시간을 연결하라. 동기가 약하면 Character Builder에 변경을 요청하라.
3. 사건이 이용한 세계의 허점은 exploits 링크로 표시하고, reason에 이 세계에서 가능했던 이유를 적어라. 허점 자체의 정당화는 World Builder에 요청하라.
4. 사건이 남길 기록을 설계하라. 기록마다 원인, 작성자, 생성 시각, 저장한 서비스(service_id)와 기록 유형(artifact_type), 조사 현재 시점의 상태를 정하라. 본문 생성 없이도 핵심 결론이 추론 가능한지 확인하라.
5. 플레이어가 가질 법한 초기 해석, 모순, 재해석을 설계하되 실제 플레이어의 생각을 확정 사실로 쓰지 마라. 해답에 필요한 사실과 규칙이 해답 전에 드러나는지 [공정성 점검](references/plot-and-branches.md#공정성)으로 확인하라.
6. 선택 당시 알 수 있는 정보, 가능한 행동, 상태 변화와 결말을 연결하라. 공통 과거 진상을 결말별로 바꾸지 마라.
7. 담당 객체 Fact·Event·Trace·Choice·Ending과 관련 링크 변경안을 반환하라. 다른 인물의 Claim·Knowledge는 해당 담당자에게 요청하라.

## 수정·검토

원인 없는 우연이나 마지막 문서 하나의 설명에 의존하는 해결을 점검하라. 필수 기록의 접근 경로가 없으면 임의의 관리자 권한으로 해결하지 말고 세계·서비스 규칙과 함께 수정하라. 결말 조건을 구체화할 때 Canon Manager의 조건 문법과 validator를 사용하라. 서사적 설득력은 도구 결과와 별도로 검토하라.

구조화 snapshot이 있으면 `canon.py timeline snapshot.json`으로 전체 사건·기록·발언을 시간순으로 보고, `canon.py validate`에서 다음 규칙을 확인하라.

| 규칙 | 사건 설계에서의 의미 |
|---|---|
| TIME-001 | 과거 사건이 조사 현재 시점보다 늦다 |
| TIME-002 / GRAPH-001 | 원인이 결과보다 늦거나 인과가 순환한다 |
| TIME-003 | 기록이 원인 사건보다 먼저 생겼다 |
| TIME-005 / TIME-006 | 서비스 출시 전의 기록, 아직 없던 조직의 행동, 효력이 없는 규칙에 기댄 사건 |
| SPACE-002 / SPACE-003 | 한 인물이 같은 시각에 두 장소에 있거나 이동 시간이 부족하다 |
| DATA-001 / DATA-002 | 보존 기간이 지나 남아 있을 수 없는 기록, 서비스가 만들지 않는 종류의 기록 |
| WORLD-004 / FAIR-001 | HARD 규칙을 이용했거나, 해답에 쓰인 숨은 규칙을 플레이어가 볼 기록이 없다 |

## 공통 계약

이 묶음은 게임마다 독립 세계를 만들고, 고정된 과거 진상과 플레이어 선택에 따른 결말을 연결한 기획서를 완성한다. 사건 밖의 운영·문화·서비스·인물 일상도 설계한다.

현재 `project_id`, `version_id`, 기준 리비전과 관련 확정 설정부터 읽는다. 다른 프로젝트·버전의 설정을 자동 상속하지 않는다. 사용자 결정은 CONFIRMED, AI의 새 창작은 PROPOSED로 구별한다. 이번 요청이 이미 승인한 범위를 반복 승인받지 않는다. 선택에서 필연적으로 따라오는 제약과 추가 가정을 구별한다.

설정 수정은 담당 영역의 변경안으로 반환한다. 타 영역을 바꿔야 하면 대상 ID·이유·영향을 명시한다. 저장 성공은 실제 도구 결과를 확인한 경우에만 보고한다. 출력은 변경 내용, 결정 근거, 미정 항목, 검토 이슈, 다음 작업을 포함한다.

구조화 파일·동기화가 필요하면 같은 묶음의 `notion-canon-manager`를 이름으로 찾아 `references/data-contract.md`를 읽는다. 저장 경로는 설치 시 달라질 수 있으므로 다른 스킬의 절대 경로나 생성 ID를 하드코딩하지 않는다. 함께 설치된 스킬이 없으면 해당 의존성을 알리고 초안은 이어가되 연동 완료를 주장하지 않는다.

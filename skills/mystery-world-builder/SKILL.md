# Mystery World Builder

사건이 없어도 성립하는 세계를 설계하라. [세계 설계 계약](references/world.md)에 따라 전체 윤곽을 잡고, 정한 범위의 운영과 생활을 충분히 상세화하라.

1. 시대·장소·현실성·기술·주요 생활권에서 이미 주어진 설정과 미정을 분리하라.
2. 사회적 가치, 제도, 역사와 주요 조직의 관계를 연결하라.
3. 조직의 목적·재원·의사결정·공식 규정·실제 관행·보상·금기를 정의하라.
4. 서비스의 정상 이용 이유와 과정, 데이터·권한·지원·실패·예외를 정의하라.
5. 사건 밖의 평범한 사용과 내부 갈등이 설명되는지 확인하라. 모든 배경을 단서로 만들지 마라.
6. 사건의 가능·불가능 조건, 생성될 기록, 인물에게 가해지는 압박을 다른 담당 영역에 전달하라.

WorldRule·Organization·Service 객체와 관련 관계를 소유한다. 인물의 개인적 동기나 사건의 진상을 조직 소개에 숨겨 확정하지 마라. 기존 규칙 변경 시 영향받는 사건·기록·접근·지식 제한을 함께 표시하라.

## 공통 계약

이 묶음은 게임마다 독립 세계를 만들고, 고정된 과거 진상과 플레이어 선택에 따른 결말을 연결한 기획서를 완성한다. 사건 밖의 운영·문화·서비스·인물 일상도 설계한다.

현재 `project_id`, `version_id`, 기준 리비전과 관련 확정 설정부터 읽는다. 다른 프로젝트·버전의 설정을 자동 상속하지 않는다. 사용자 결정은 CONFIRMED, AI의 새 창작은 PROPOSED로 구별한다. 이번 요청이 이미 승인한 범위를 반복 승인받지 않는다. 선택에서 필연적으로 따라오는 제약과 추가 가정을 구별한다.

설정 수정은 담당 영역의 변경안으로 반환한다. 타 영역을 바꿔야 하면 대상 ID·이유·영향을 명시한다. 저장 성공은 실제 도구 결과를 확인한 경우에만 보고한다. 출력은 변경 내용, 결정 근거, 미정 항목, 검토 이슈, 다음 작업을 포함한다.

구조화 파일·동기화가 필요하면 같은 묶음의 `notion-canon-manager`를 이름으로 찾아 `references/data-contract.md`를 읽는다. 저장 경로는 설치 시 달라질 수 있으므로 다른 스킬의 절대 경로나 생성 ID를 하드코딩하지 않는다. 함께 설치된 스킬이 없으면 해당 의존성을 알리고 초안은 이어가되 연동 완료를 주장하지 않는다.

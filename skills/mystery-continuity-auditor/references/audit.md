# 검토 기준

| 검사 | 확인할 내용 |
|---|---|
| 시간·인과 | 선행 조건, 실제 시각·기록 시각, 행위자의 위치·접근이 양립하는가 |
| 지식 | 작성·행동 시점 이전에 해당 정보를 얻을 경로가 있는가 |
| 정체성·관계 | 동일 인물의 식별과 관계가 시점별로 일관되는가 |
| 시스템 | 인증·보존·삭제·관리자 권한이 기록과 접근을 허용하는가 |
| 세계 자립성 | 사건 밖의 운영·문화·사용자 가치·생활이 성립하는가 |
| 근거 | 결론을 지지·반박하는 관계에 추론 설명이 있고 대안 해석을 고려하는가 |
| 조사 | 주요 정보가 발견 가능하고 단일 우연·불가능한 접근에만 의존하지 않는가 |
| 반전 | 이미 본 정보의 재해석에 근거가 있고 조기 노출 문제가 없는가 |
| 결말 | 같은 과거 진상에서 선택이 결과를 만들며 각 조건에 도달할 수 있는가 |
| 변경 | 수정된 객체의 직접·간접 의존 항목이 재검토됐는가 |
| 프로젝트 | 다른 게임·버전의 설정이나 ID가 유입되지 않았는가 |

BLOCKER: 핵심 사건이나 필수 결말이 성립하지 않음, 과거 진상 모순, 핵심 정보 경로 불가능. MAJOR: 중요한 인과·동기·근거가 부족하나 설계 수정으로 해결 가능. MINOR: 주변 표기·세부 설명 문제.

이슈에는 title, severity, affected_ids, evidence, violated_rule, suggested_fix, status를 기록한다. 자동 검사 결과와 의미 검토 결과를 별도 evidence로 남긴다. 수정 후 해당 이슈와 영향 범위를 재검토한다.

구조 검증은 ID·참조·상태·조건·대표 도달 경로를 검사한다. 자연어 진실성, 심리적 개연성, 실제 플레이 재미를 증명하지 않는다. 주요 미정이 남으면 ‘완성’ 대신 ‘초안, 다음 결정 필요’로 보고한다.

# Mystery Production Orchestrator

사용자의 창작을 이끄는 진행자로 작업하라. 사용자가 데모를 요청하지 않으면 실제 프로젝트를 진행하라. 이 스킬의 엔드투엔드 완료 범위는 기획서와 Notion 기록이며 게임 코드나 기록 본문의 대량 생성은 별도 요청 범위다.

## 시작

1. 이미 답변한 선호와 제공한 아이디어를 읽어 결정·제안·미정을 분리하라.
2. 기존 프로젝트면 Canon Manager로 Project Hub, 활성 버전, 마지막 Session과 관련 설정을 읽어라. 새 프로젝트면 독립 ID와 빈 상태를 만들고 Notion 대상 부모가 지정되어 있으면 그곳에 템플릿을 적용하라.
3. 저장 대상이 지정되지 않았으면 먼저 진행할 수 있는 창작 질문을 하라. 실제 Notion 생성 전에 대상 페이지를 묻거나 사용자가 요청한 워크스페이스 최상위 위치를 사용하라. 연결되지 않은 상태에서도 초안을 진행하되 저장 대기 상태를 표시하라.
4. 가장 영향이 큰 미정 쟁점 하나를 골라 [워크숍 규칙](references/workshop.md)에 따라 질문하라. 질문 순서와 결과물 목차를 동일시하지 마라.

## 작업 라우팅

| 필요 | 스킬 |
|---|---|
| 핵심 미스터리, 과거 진상, 사건 순서, 조사·분기 결말 | mystery-plot-builder |
| 사회·역사·일상·조직·서비스의 자립적 운영 | mystery-world-builder |
| 인물 정체성·생활·동기·관계·시점별 앎과 주장 | character-knowledge-builder |
| 모순 검토·변경 파급·기획 완료 판정 | mystery-continuity-auditor |
| Notion 템플릿·Canon 조회와 기록·기획서 조립 | notion-canon-manager |

필요한 스킬의 SKILL.md를 읽고 그 책임의 작업을 수행하라. 스킬을 별도 실행 프로세스나 자동 서브에이전트로 간주하지 마라. 라우팅을 이유로 내부 구현을 사용자 질문에 노출하지 마라.

## 한 답변 이후

선택된 설정, 필수 파급, 아직 제안인 내용을 짧게 구별하라. 모순이 있으면 어느 기존 결정과 충돌하는지 드러내고 수정 대안을 비교하라. 세계·인물·사건 중 관계된 영역만 보완하고 검토하라. 다음 질문 전에 결정과 재개 상태를 저장하라. 연결 실패 시 재시도는 Canon Manager의 제한을 따르고 창작 진행을 불필요하게 중단하지 마라.

## 완료와 재개

[완료 기준](references/completion.md)으로 기획을 점검하고 Canon Manager의 기획서 템플릿으로 조립하라. 중요한 미정·모순이 있으면 초안으로 표시하라. 끝없는 확장을 피하고 정한 세계 범위가 충분히 완성됐으면 기획서를 전달하라. 사용자가 완성을 요청해도 핵심 선택을 대신 확정하지 말고 필요한 창작 제안과 미정을 표시하라.

세션 마지막에 활성 버전, 마지막 질문과 답변, 다음 쟁점의 이유, 열린 이슈, 저장 상태를 기록하라. 재개 시 최근 메시지나 파일명만으로 다른 버전을 선택하지 마라.

## 공통 계약

이 묶음은 게임마다 독립 세계를 만들고, 고정된 과거 진상과 플레이어 선택에 따른 결말을 연결한 기획서를 완성한다. 사건 밖의 운영·문화·서비스·인물 일상도 설계한다.

현재 `project_id`, `version_id`, 기준 리비전과 관련 확정 설정부터 읽는다. 다른 프로젝트·버전의 설정을 자동 상속하지 않는다. 사용자 결정은 CONFIRMED, AI의 새 창작은 PROPOSED로 구별한다. 이번 요청이 이미 승인한 범위를 반복 승인받지 않는다. 선택에서 필연적으로 따라오는 제약과 추가 가정을 구별한다.

설정 수정은 담당 영역의 변경안으로 반환한다. 타 영역을 바꿔야 하면 대상 ID·이유·영향을 명시한다. 저장 성공은 실제 도구 결과를 확인한 경우에만 보고한다. 출력은 변경 내용, 결정 근거, 미정 항목, 검토 이슈, 다음 작업을 포함한다.

구조화 파일·동기화가 필요하면 같은 묶음의 `notion-canon-manager`를 이름으로 찾아 `references/data-contract.md`를 읽는다. 저장 경로는 설치 시 달라질 수 있으므로 다른 스킬의 절대 경로나 생성 ID를 하드코딩하지 않는다. 함께 설치된 스킬이 없으면 해당 의존성을 알리고 초안은 이어가되 연동 완료를 주장하지 않는다.
